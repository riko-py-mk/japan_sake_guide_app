🎯 Project Overview

The Japanese Sake Guide App is a bilingual (English / Japanese) web application that acts as an AI-powered sake sommelier. Users chat with an agent that can search sake rankings, retrieve brand information, surface social-media content, locate nearby sake shops and restaurants on an interactive Google Map, and find online retailers for purchasing sake.

🏗️ Architecture & Data Flow

High-Level Data Flow

When a user submits a message the Streamlit frontend calls run_sake_agent(), which feeds the message into the LangGraph state machine. The agent decides which tools to invoke, executes them, and returns a final response. If the response contains embedded MAP_DATA_START / MAP_DATA_END markers the UI extracts the JSON and renders an interactive Google Map.

📦 Module Breakdown

app.py — Streamlit Application Entry Point

All Streamlit page logic lives here. Key responsibilities:

  • check_api_keys() — Validates OPENAI_API_KEY and TAVILY_API_KEY; warns if Google Maps key is absent.
  • initialize_agent() — Builds the compiled LangGraph agent once per session, stored in st.session_state.agent.
  • render_sidebar() — Language toggle (en / ja), categorised example prompts, data source links, clear-chat button.
  • extract_map_data(response) — Regex-parses MAP_DATA_START … MAP_DATA_END blocks from the agent response and returns a dict.
  • display_map(map_data) — Injects a full Google Maps JavaScript API page into the chat via components.html(). Renders markers, info windows with photos and reviews, and clickable Google Maps links.
  • process_user_input(user_input) — Orchestrates one chat turn: call agent, strip map markers, render text then map.
  • render_chat_tab() / render_network_tab() — Content for the two main tabs.

agents/sake_agent.py — LangGraph Workflow

Defines the AgentState TypedDict and assembles the cyclic workflow. Two flavours of the LLM are bound at construction time: 

llm_with_tools               # Normal: LLM chooses tools freely
llm_with_forced_location_tool # tool_choice=search_sake_places, used when _is_location_query() is True

The system prompt (~100 lines) instructs the agent on its sommelier persona, available tools, bilingual response rules, and critically — when to use search_sake_places vs. search_sake_rankings.

Key design decision in run_sake_agent(): For location queries, the function iterates the final messages in reverse to find the most recent ToolMessage that contains MAP_DATA. It uses that raw tool output as the response text rather than the LLM's summary. This prevents text/map mismatch where the LLM might hallucinate its own list of places that don't match the actual Google Places results embedded in the map JSON.

agents/tools.py — Tool Definitions

All seven agent tools are @tool-decorated closures created inside the factory create_sake_tools(tavily_api_key, instagram_access_token, google_maps_api_key). Using closures binds API clients to each tool without exposing keys in global scope.

utils/helpers.py — Language & Prompt Utilities

detect_language(text) counts Japanese characters (Hiragana U+3040–309F, Katakana U+30A0–30FF, Kanji U+4E00–9FFF); if >20% of alpha characters are Japanese it returns "ja". The bilingual SIDEBAR_EXAMPLE_PROMPTS and EXAMPLE_PROMPTS dicts drive the sidebar and welcome screen buttons.

utils/sake_network.py — Network Graph

Loads sake_ranking_fallback.json (refreshed nightly by GitHub Actions) and uses streamlit-agraph to render a physics-enabled force-directed graph. Three node shapes represent sake brands (dot), prefectures (box), and flavor types (ellipse). Colors encode both flavor type and geographic region.

config/settings.py — Settings Dataclass

Settings is a simple @dataclass holding API keys, model name, temperature, and ranking URLs. get_settings() reads from st.secrets and raises KeyError if required keys are absent.

Smart Location Forcing

Inside call_model(), before invoking the LLM, the agent checks whether the latest human message is a location query using _is_location_query(). This function scans for Japanese keywords like 場所, 飲める, 買える and English keywords like where to buy, shop, find. If it matches and no tool calls have been made yet, the LLM is invoked with tool_choice forced to search_sake_places, guaranteeing that a map is always produced for place queries rather than having the model answer from memory.

MAP_DATA Protocol

search_sake_places appends a special sentinel block to its return string: 

==================================================
MAP_DATA_START
{"search_location": "Tokyo", "center_lat": 35.68, "center_lng": 139.69, "locations": [...]}
MAP_DATA_END
==================================================

app.py uses a regex with re.DOTALL to extract and JSON-parse this block. The surrounding text is stripped from the chat display, and the JSON is passed to display_map() which renders an embedded Google Maps JavaScript API component.

Bilingual Language Detection

Both agents/sake_agent.py and agents/tools.py contain a local _is_japanese(text) helper that checks for any Unicode character in the Hiragana, Katakana, or CJK Unified Ideograph ranges. Tools build different search queries depending on detected language (e.g., Japanese queries get 日本酒 ランキング おすすめ prefix).

Edge Semantics

Each sake brand node has two edges: one to its home prefecture node and one to its flavor type node. Edge color mirrors the target node's color, making the graph readable at a glance. The physics simulation (physics=True) causes related nodes to cluster naturally.

📐 Key Patterns & Conventions

Tool Error Handling

All tools catch exceptions and return error strings rather than re-raising. This prevents the LangGraph tool node from crashing the agent and lets the LLM surface the error message to the user gracefully. 

try:
    results = tavily_client.search(...)
    return formatted_results
except Exception as e:
    return f"Error searching sake rankings: {str(e)}"

Content Truncation

Search result content strings are truncated to 300–600 characters (depending on tool) before being assembled into the tool return value. This keeps token usage bounded and avoids context overflow in long sessions.

Hashtag Sanitization

_sanitize_hashtag(text) strips the leading # and removes all characters except alphanumerics and Japanese scripts, then lowercases the result. This produces valid hashtag search terms regardless of whether the user included the # or used mixed-script input.

Adding a New Tool

Follow these four steps:

  1. Add a @tool-decorated function inside create_sake_tools() in agents/tools.py.
  2. Append it to the return list at the bottom of the factory function.
  3. Update the system prompt in sake_agent.py (the Available Tools: section) to document the new tool.
  4. Optionally add example prompts to SIDEBAR_EXAMPLE_PROMPTS in utils/helpers.py.
Testing Checklist Test with both English and Japanese queries. Verify ranking searches, specific sake lookups (e.g., "Dassai", "獺祭"), hashtag searches (#日本酒, #sake), Twitter search, Instagram search, search_sake_places with and without sake_name, map display with photos and reviews, and online shop search.
